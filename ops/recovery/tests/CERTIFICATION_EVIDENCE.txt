--- pg_ctl status exit-code cleanup-safety correction ---
pg_ctl status: 0=running, 3=stopped, 4=inaccessible/unspecified data dir, other=error. A destructive
rm proceeds ONLY on a POSITIVE confirmed-stopped (exit 3); 0 and any other code (UNKNOWN) refuse +
preserve + non-zero + retry. Shared rec_pg_confirmed_stopped (lib.sh) + eph_pg_confirmed_stopped
(eph_tracking.sh). Applied in eph_safe_remove_root, setup --down, and the failed-setup cleanup_up
trap -- which guards whenever a START WAS ATTEMPTED (not only on start success), because pg_ctl -w
start can exit non-zero with the postmaster still running (e.g. PGCTLTIMEOUT); gating on success
would skip the stop+confirm and rm a live cluster. Tests: A running(0)->refuse, B/E stopped(3)->
permit+retry, C status4->refuse, D error->refuse, F main unchanged; provisioner 19 (setup --down
on status4) + 20 (start-reports-failure-but-running -> failed-setup cleanup preserves the live dir).
